# Playbook: Due Diligence Support

> Hijack assembles a DD support pack for a deal: a structured checklist, a scored
> rubric, the regenerative-impact assessment, and a red-flags list. Hijack
> populates and summarises; humans judge. The go/no-go stays with Arthur and IC.

## Trigger

- On demand: "Build a DD support pack for <deal>."
- When a deal enters `In DD` and Arthur asks for support.

## Source

- The deal's **Deal Flow** page and its child sections: DOCUMENTS (Legal, KYC,
  Materials), DUE DILIGENCE (Dataroom, DDQ), TIMELINE.
- Linked Stakeholders (founders/team) and any meeting notes.

## Output

A DD support pack written to the sandbox (or as a structured comment), dated and
linked to the deal:

```
# DD Support Pack — <deal> — <YYYY-MM-DD>
> Drafted by Hijack — review before use. Scores are inputs for IC, not verdicts.

### 1) Checklist (nine areas)
Status per area: Complete / Partial / Missing, with what's outstanding.
- Finance · Tax · Legal · HR · Assets · IT · Products/Services ·
  Marketing & Sales · Founder background

### 2) Scored rubric (1–5, team weighted)
| Axis | Score | Evidence | Gaps |
| --- | --- | --- | --- |
| Team / founders | | | |
| Market fit | | | |
| Financial health | | | |
| Legal / compliance | | | |

### 3) Impact assessment (IMP Five Dimensions)
Equal-weight gate for SR's regenerative mandate.
| Dimension | Note |
| --- | --- |
| What (outcome) | |
| Who (stakeholders) | |
| How Much (scale/depth/duration) | |
| Contribution (vs counterfactual) | |
| Risk (impact risk) | |
- Additionality: yes / no / unclear — with reasoning.

### 4) Red flags
- Multi-select style list: e.g. inconsistent financials, team turnover, legal
  disputes, regulatory issues, cap-table/IP concerns, market decline.

### 5) Open items before IC-ready
- What must close (incl. KYC/compliance) before this deal advances.
```

## Rules

- **Every score and status cites its evidence** (a document, a DDQ answer, a
  meeting note). No evidence → mark Missing/unclear, don't score.
- **Never fabricate** financials, legal facts, or impact claims. Summarise what's
  in the dataroom/DDQ; flag gaps.
- **Two equal gates:** a deal is not "IC-ready" until both the financial rubric
  and the impact assessment are complete. State clearly when it isn't.
- **KYC is a hard gate** toward `Executed` — always list it if unconfirmed.
- This pack is decision *support*. Do not write a recommendation to invest;
  present evidence, scores, and open items for Arthur and IC to judge.

## Quality bar

- Could Arthur walk into IC with this pack and immediately see what's solid,
  what's missing, and what blocks advancement? Every claim traceable to a source?
